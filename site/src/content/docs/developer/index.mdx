## Start here

1. Read the repository `AGENTS.md`.
2. Read `docs/architecture/README.md`.
3. Read the applicable ADR/spec/milestone.
4. Read `docs/engineering/DEVELOPMENT.md` and `docs/engineering/ISSUE-PROTOCOL.md`.
5. Work only from a GitHub Issue that has passed the Ready gate.
6. For implementation/fix/code work on an Issue, use `.agents/skills/implement-issue/SKILL.md` before production edits.

## Claim an implementation Issue

New implementation Issues stay unassigned. Seyal uses the exact remote `issue/<number>` branch as the atomic claim so parallel contributors cannot claim the same Issue. Never set, clear, or change an Issue assignee during pickup, handoff, or release.

```text
fresh open Issue whose body `State` field is Ready, checklist, and dependency check
→ authenticated identity from `gh api user --jq .login`
→ implementation plan and confirmation in an Issue comment
→ atomic creation of exact remote issue/<number> from accepted master SHA
→ fresh Issue/branch verification
→ claim comment with claimant, branch, base SHA, and plan link
→ isolated worktree
→ implementation
```

Only the successful remote branch creator proceeds with a new claim. If the exact branch already exists, stop unless its recorded owner explicitly asked to resume, handed it off to you in an Issue comment, or a maintainer resolved a stale claim. Never create a suffix branch; claims do not expire automatically. Existing assigned work stays with its owner unless that owner explicitly hands it off, and the assignee field remains unchanged. A planning parent does not lock an independent Ready child when its dependencies and scope boundaries are clear.

For the complete pickup, handoff, release, and conflict procedure, see the [Issue protocol](https://github.com/seyal-org/seyal/blob/master/docs/engineering/ISSUE-PROTOCOL.md) and [development workflow](https://github.com/seyal-org/seyal/blob/master/docs/engineering/DEVELOPMENT.md).

When this guide conflicts with an accepted source-of-truth document, the source-of-truth document wins and this guide must be corrected.
