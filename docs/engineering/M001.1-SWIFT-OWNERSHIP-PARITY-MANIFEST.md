# M001.1 freeze: deprecated Swift shell and authority map

Parent: [#878](https://github.com/mahboobmonnamd/seyal/issues/878). This Issue: [#886](https://github.com/mahboobmonnamd/seyal/issues/886).

Authority: [#875](https://github.com/mahboobmonnamd/seyal/issues/875) / PR `#876` (`3ff15fe`), ADR-015 / [#877](https://github.com/mahboobmonnamd/seyal/issues/877).

Owner-accepted M001.1 **execution** (not an ADR change): the current headed Swift shell is **deprecated**. It is not product authority. M001.1 does not port it in place and does not treat its XCTest/XCUI suite as Done.

```text
freeze head: 3ff15feff6ed54da74efad7a7829050115e696fd
```

## Execution contract

```text
1. Freeze current Swift shell
   → deprecated
   → no feature work
   → not product authority

2. Build new product behavior entirely in Rust
   → Workspace/Tab/Pane
   → Blocks/composer
   → Flow/Raw/TUI
   → theme/config
   → recovery
   → Rust tests

3. Build NEW minimal Swift host from scratch (#883)
   → AppKit/window
   → IME
   → accessibility
   → Metal/native plumbing
   → forward events to Rust
   → render Rust-owned state

4. Prove new headed Seyal.app works

5. Delete old Swift shell + obsolete XCTest
   in the replacement PR (with #883/#884)

6. Merge only when real Seyal.app works (#885)
```

ADR-015 still holds: this repository keeps a thin native host. Rust must not impersonate AppKit/IME/VoiceOver/Metal. There is no second Swift UI tree.

Frozen `macos/Seyal` may keep compiling so `make check` still has a binary. That is CI continuity, **not** permission to extend `SeyalShellState` or to treat green XCUI as product proof.

## Boundary rule

| Kind | Meaning |
|---|---|
| **RUST** | New portable product. Implement under #879/#880/#740/#861/#881/#882. Do not grow the equivalent Swift reducer. |
| **NEW HOST** | Allowed in the from-scratch AppKit/Metal host (#883). Write new, or copy only platform glue from freeze head if it is still correct. |
| **DEPRECATED** | Old shell/product/test. No feature work. Delete in the replacement PR. |

If a second desktop OS would have to rewrite the logic, it is **RUST**. If it is an Apple API, it is **NEW HOST**.

Rust homes: reuse `seyal-runtime` (Workspace / BlockTimeline), `seyal-client` (host-side recovery, composer draft, cold config resolve), `seyal-core` (semantic value types). Do not add a GUI framework crate. `seyal-client → seyal-runtime` production dependency remains forbidden.

Metal renderer-local retry in `MetalSurfaceView` is GPU/presentation, not #882 client recovery.

## Dual-authority rule

Until the replacement PR:

- Do not add features to deprecated Swift product types.
- Do not make Swift call a new Rust reducer *and* keep `SeyalShellState` as a second writer.
- Old XCTest going green is not M001.1 progress.
- Rust tests are the product spec for step 2.
- Headed proof is the **new** `Seyal.app` (steps 4–6), not the frozen shell.

## What this document is not

Not a promise to preserve old UX. Not new performance thresholds. Pass 6/10 Metal/Candidate-D engineering records remain renderer/transport constraints (`docs/engineering/M001-PASS6-METAL-RENDERER.md`, `docs/engineering/PERFORMANCE.md`) and are re-measured on the new host under #885.

Independent review of this freeze is required before #879+ production pickup treats old XCUI as a gate.
