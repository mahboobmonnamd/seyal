# Security policy

For security engineering requirements, see [`docs/engineering/SECURITY.md`](docs/engineering/SECURITY.md).

Do **not** report suspected exploitable vulnerabilities, credentials, secrets, customer data, or sensitive terminal contents in a normal GitHub Issue.

Use the repository's private GitHub Security Advisory flow instead:

`Security` → `Advisories` → `New draft security advisory` / private vulnerability reporting when enabled.

Non-sensitive security architecture/R&D work may use the normal Architecture/R&D Issue form.
